# Ainvil — notes for Claude sessions

The spec is `DESIGN.md`. The user-facing docs are `README.md`.

## Shape
- Everything is in `index.html`: CSS, markup, and one inline `<script>`. There's no build step and no dependencies. Ask the user before adding any.
- The default workflows (ComfyUI **UI format**) sit in `<script type="application/json" id="default-workflows">` as `{Anima: {mode: wf}, MOSS: {…}}`. They're generated from `workflows/{,moss-}*-minworkflow-cads.json` by `tools/embed-workflows.py`, so don't hand-edit that blob. The plain `*-minworkflow.json` files are the Anima graphs without the CADS node (handy for testing the "not configured" path).
- The MOSS workflows are made from the Anima ones by `tools/make-moss-workflows.py`, which keeps the node ids, so both use `defaultFw()`'s mappings. MOSS adds Skip Layer Guidance: #64 `SkipLayerGuidanceDiTSimple` and #65 `ComfySwitchNode` (LoRA chain vs. SLG → CADS), driven by custom parameters. `workflows/image_moss_image_t2i.json` is ComfyUI's original MOSS template (subgraph, not used directly).
- The default custom workflow (Extras) "Upscale with model" is `workflows/upscale_with_model.json`, embedded by the same script into `<script type="application/json" id="default-custom-workflows">` as `{upscale_with_model: wf}`. Its parameters are in `defaultUpscaleCw()` (node ids #2 LoadImage, #9 UpscaleModelLoader, #11 ImageScale, #12 ComfySwitchNode "Model upscale only" (true = skip #11), #5 SaveImage).
- The app default is `http://localhost:8188/`.

## Key design decisions
- **Workflows are stored as provided** (UI or API format). `toApi()` converts UI→API at use time:
  - It handles links, Reroute, PrimitiveNode, muted (mode 2) and bypassed (mode 4) nodes.
  - For widget values it prefers `widgets_values_named`, then `/object_info` input order, skipping `control_after_generate` values.
  - Subgraphs are rejected.
  - Node types the server doesn't know are dropped as frontend-only, unless they have linked outputs. Those are kept (e.g. CADS without comfyui-cads), so mappings still find them and `buildPrompt` can bypass them.
- **Mappings** are `{node, input}` targets keyed by functional parameter, one set per mode. Node ids are the same in UI and API format. The parameter list is `FPARAMS`. Structural parameters:
  - `lora` clones and chains the template node; zero LoRAs remove it.
  - `batch_repeat` inserts `RepeatLatentBatch`.
  - `output` swaps SaveImage→PreviewImage when saveImage is off.
  - `resize` (node only, img2img/inpainting): the ImageScale (#53) that sizes the input image. `applyResize()` sets `serverPreferences.scaleMethod` and, when it enlarges `p.src`, puts `addModelUpscale()` in front (`serverPreferences.upscaleModel`, '' = none). It runs after the custom parameters, so an old "Resize method" custom parameter loses. At the same size it is left alone (ImageScale passes the image through unchanged), so Load from PNG still finds width/height there.
  - `cads` (node only): the CADS node gets its inputs from `gen.cads` (`CADS_FIELDS`), with seed = image seed mod 2^32. When `cadsActive()` is false, `bypassNode()` removes the node and passes its model input through.
- **Denoise** is shown as a start step: `denoise = 1 - step/steps`. In txt2img it is always 1.
- **Inpainting**: the image is uploaded with `/upload/image`. The mask is then uploaded with `/upload/mask` and `original_ref`, which writes alpha = 255 - mask into a server-side copy. This keeps the original RGB under the mask; client-side alpha compositing would lose it to premultiplication. Uploads go to `input/ainvil/` with content-hash names and are cached per server.
- **Focused inpainting** (`gen.inpaintMode` 'whole' | 'focused', `gen.ctxMode` 'auto' (By Size, border `gen.ctxBorder`) | 'manual'): `ctxBox()` is the context window in whole image pixels. `input.maskBounds` is kept by `setMask()` (use it for every mask change); the manual box is `input.ctxBox` (floats, not saved, kept when a same-size image is loaded) and is always conformed to the generation aspect ratio (`conformBox`). `ensureUploads()` uploads the crop of image + mask and returns `{image, src, focus}`; `addPasteBack()` adds a LoadImage of the original, RepeatImageBatch for batch size > 1, the scale-back (`addScale()`, also Scaling prefs; skipped at the same size) and ImageCompositeMasked through the crop LoadImage's MASK, then rewires the output nodes. Added nodes have `_meta.title` from `AINVIL_NODES` ("Ainvil …"): `matchPrompt` ignores them and `promptFocus()` reads the window back (the titles survive in the PNG prompt). The mask editor has a Window tool (`me.tool`) that edits `me.box`, committed on Done. Its Crop button (`meCrop()`, shown with the Window tool) crops image + edited mask to the box, makes it the input image and `stashAdd()`s it.
- **Image editor** (click the input image, `#imageEditor`, state `ie`): edits a canvas copy of `input.img`. Tools `ie.tool` paint / erase (strokes with `createPattern(input.img)`, so it restores the original) / fill (`ieFloodFill`, scanline, per-channel tolerance) / select (`ie.sel`, whole pixels, clips the other tools) / pick (eyedropper, also Alt+click) / pan. Clear also deselects. Paint and fill call `ieUseColor()`, which keeps `clientPreferences.recentColors` (`RECENT_COLORS` = 6, shown in `#ieRecent`). Zoom: `ie.zoom` multiplies `fitStage()`'s fitted size (the brush stays in screen pixels) and `ie.panX/panY` translate `#ieWrap`; `ieZoom()` keeps the point under the pointer fixed, max `IE_MAX_SCALE` screen px per image px. Panning (Pan tool, `ie.space`, middle button) is handled by a capture-phase pointerdown on `#ieStage`, so it never reaches the canvas. Done (`ieDone`, only if there are undo entries) and Crop (`ieCrop`) go through `ieApply()`: `setInputImage` (keeps the mask at the same size; Crop crops it) + `stashAdd`. Undo snapshots are capped by `IE_UNDO_BYTES`. It shares `fitStage`, `canvasPos`, `showRing`, `boxHit`/`boxCursor` and `cropCanvas` with the mask editor.
- **Images** are fetched with CORS into blob URLs. Firefox blocks `<img src="http://…">` from `file://` pages.
- `%date:…%` / `%Title.widget%` in `filename_prefix` are expanded client-side, because the ComfyUI server doesn't do it.
- **Generate jobs** (`jobs`, `runningJob` = `jobs[0]` while it runs): each Generate press is a job. `prepare()` reads the whole form before its first await (`collectParams()` is a `structuredClone`, `ensureUploads()` reads `input`/mask/window up front), so the form can change while jobs wait; the prompts are built then and queued on the server only when the job starts (`runJob`). `busy` = any job. Skip (`skipGenerate`) sets `p.skipped` on `job.cur`, deletes it from the server queue and interrupts it by prompt id; `waitForPrompt()` then returns null. ComfyUI reports an interrupted prompt with `status_str: 'error'`, so the interrupt check comes first. Cancel = `cancelJob(runningJob)`; a queued job is just removed. Client Preferences `multipleJobs` (Generate disabled while busy when off, `#btnJobs`/`#jobsDlg` hidden), `galleryClear` ('generate' | 'jobStart' | 'never') and `autoStash` ('no' | 'auto' | 'all') go through `clearGallery(auto)`.
- Completion is detected by polling `/history/{id}`. The WebSocket is only used for progress, queue display and live preview. Live preview handles binary frames: type 1 (u32 format, image) and type 4 (u32 metadata length, JSON, image). It is shown only when `serverFeatures.livePreview` and `clientPreferences.showLivePreview` are both on (`livePreviewOn()`).
- Combo options (models, samplers, LoRAs, custom combos) come from `/object_info` for the mapped node's class/input. Models and LoRAs are then filtered by the workflow's regex.
- `serverPreferences` holds `saveImage`, `scaleMethod` (default lanczos) and `upscaleModel` (default '').
- `clientPreferences` in the config holds gallery columns/rows, the mask display color and the image editor's recent colors. The mask canvas's RGB is only for display (`recolorMask()`): only alpha is the mask, so changing the color doesn't change upload hashes.
- The full-screen viewer tries the direct `/view` URL first, because ComfyUI's `Content-Disposition` filename then names "Save Image As". From `file://`, Firefox refuses it, so the viewer falls back to the blob URL inside an `<a download>` link.
- **Load from PNG** (drop on `#sec-main`, `loadSettingsFromPng`): reads the API `prompt` chunk, then `matchPrompt()` picks the fw/mode whose template nodes match by id + class. LoRA clones, RepeatLatentBatch, the "Ainvil …" scaling/paste-back nodes and SaveImage↔PreviewImage don't count against the match. Values are read back through the mappings. For our inpainting uploads (`ainvil_<hash>_m<mh>.png`), the RGB comes from the original `ainvil_<hash>.*` (alpha premultiplication again), and the mask is `255 - alpha` of the `_m` file. Custom values that are just the expansion of a `%…%` template are not loaded.
- **Server history** (Output Gallery → History…, `#historyDlg`): `GET /history?max_items=N` (in-memory, all clients), sorted by prompt number. `historyEntry()` reads it through `matchPrompt()`/`promptValue()`; **Load Settings** uses `applyPromptSettings()` (shared with Load from PNG). Thumbnails use `/view?…&preview=webp;60`, with a blob fallback for `file://`. Items added from history may have no seed (`seed == null`).
- **Image stash** (Output Gallery → Stash…, `#stashDlg`): client-side, in IndexedDB `ainvil-stash` (store `images`, keyPath `id` = `hash53` of the bytes, so re-stashing moves it to the top). Records keep the blob plus the history entry's metadata (`a`, number, text, seed, model); `stash.items` adds blob URLs as `url`/`src`, so it's a viewer/download list. Everything persists (pinned or not); Clear keeps pinned, Clear All and Reset to defaults remove all. Without IndexedDB it is memory-only, with one warning toast. History rows highlight `g.sel` (last viewed), which their Use as Input takes. `itemToInput()` is the shared Use as Input. Add to Stash buttons (Output Gallery and Extras Output = all their images (`stashAll`), input image, viewer — hidden when viewing the stash) go through `stashItems()`; the dialog's `#stashDrop` (drop or click to choose) adds files with `stashFile()`; Generate/Extras/history gallery items carry `promptMeta()`/`promptInfo()` fields (`a`, text, model, number, time) for it.
- Model/LoRA **search** (`searchList`, plain words, AND) runs on top of the workflow's regex filter (`filterList`).
- Config schema version is `CONFIG_VERSION = 1`; keep it at 1 during alpha. localStorage keys: `ainvil.config`, `ainvil.generate` (form state), `ainvil.extras` (Extras state: `{cwName, values}`), `ainvil.tab`.
- **Custom workflows / Extras**: parameters are `{name, type, default, options, filter?, hint?, min/max/step, mappings: [targets]}` (one flat target list, no modes). Types are `CW_PARAM_TYPES` = `PARAM_TYPES` + `image`; `image` is only allowed for custom workflows (`normalizeParam`'s `perMode` = functional).
  - `buildCustomPrompt()` sets the values; an unset value or empty default falls back to `cwDefault()` (the mapped input's workflow value). It expands filename prefixes with `vars` (`%input%`) and swaps SaveImage→PreviewImage when saveImage is off (`saveToPreview`).
  - Image params: images live in `exImages[cw][param]` (not saved), are uploaded with `uploadCached()` (same hash names/cache as Generate). Several images = one queued prompt per image (`exPrepare`/`exRunParams`); a single-image param is reused, mismatched counts are an error.
  - Combo options come from `cwOptions()`; the search box appears for server lists that look like files or have >12 entries.
  - Generate and Extras runs exclude each other (they share `progress` and `setProgress` drives both bars). The viewer and downloads take the image list (`gallery` or `exOut`, each with `items`, `sel`, `render`).
- The Generate layout is 3, 2 or 1 columns. `LAYOUTS` (the defaults) moves the section elements between columns; there, the dynamic-height sections (Custom Parameters, LoRA) sit at the bottom of their columns. That rule doesn't apply to user layouts.
  - User layouts: `clientPreferences.layouts[cols]` (only the changed column counts, cleaned up by `normalizeLayout`: unknown ids dropped, missing ones appended to the last column) and `clientPreferences.hiddenSections` (all column counts). Call `layout({force: true})` after replacing `config`.
  - Edit layout mode (`layoutEditing`, `#layoutBar`, `.columns.editing`): drag a section by its `<h2>` with pointer events (`ldrag`, a `.drop-line` placeholder; the section moves on release, then `saveLayout()`). `addSectionTools()` adds the Hide/Show button and "Hidden" tag to each `<h2>`; CSS shows them only while editing, and hidden sections are `display: none` otherwise. Reset clears the current column count's layout and all hidden sections.
- **CADS**: `cadsBlocker()` returns the reason it can't run: not mapped for the mode, server feature off, or no CADS class in `/object_info`. If there's none, the `gen.cads.on` master switch decides. Defaults come from the template node (`templateDefaults().cads`). A main Steps change sets `gen.cads.total_steps` (one-way). `gen.cads.seedAuto` (default true) uses image seed mod 2^32; otherwise `gen.cads.seed` is used as is (not in `CADS_FIELDS`). Load from PNG sets `on` from whether the CADS node is in the prompt, and a missing CADS node doesn't count against `matchPrompt`.

## Testing
The end-to-end suite is `tests/` (see `tests/README.md`): Gherkin features in `tests/features`, steps in `tests/steps`, and a stdlib runner/Marionette driver in `tests/ainvil_bdd`. Run `python3 tests/run.py` (`--tags '~@gpu'` skips generations, `--coverage` lists functions no scenario reaches). Add or update scenarios when behavior changes.
- Each scenario starts from empty storage with the default config pointed at the test server. The page helpers (`window.__t`) capture downloads, toasts and confirms, and simulate file pickers, drops, paste and canvas strokes.
- A guard in the page refuses prompts without `safe,` or saving outside `ainvil-test/`.

Headless Firefox driven over Marionette (raw socket, Python stdlib) works well for end-to-end checks against the test server.
- Start Firefox with `-remote-allow-system-access` if you need the chrome context (e.g. to inspect `gContextMenu`).
- Top-level `let`/`const` (`gen`, `config`, `gallery`) aren't on `window`; read them with an indirect `(0, window.eval)(…)`.
- Include `safe,` in every test prompt.
- Set the Filename prefix custom parameter to `ainvil-test/...` so test outputs land in one folder.
- Never delete outputs or other files while testing; the user cleans up.
